Tool reference

What each piece does, its options and files. Everything here runs on the machine; nothing calls home.

validity-daemon

The fingerprint service. It owns the bus name net.reactivated.Fprint on the system bus and speaks fprintd's D-Bus API, so every fprintd client works with it. The Debian and Ubuntu packages divert fprintd's D-Bus activation file to it; D-Bus starts it on demand (validity-daemon.service). It never pairs or erases the sensor by itself, and never downloads anything.

/usr/libexec/validity-daemon [OPTIONS]
--config PATH
Configuration file (default /etc/validity/validity.toml, used only if present).
--vendor-dll PATH
Synaptics driver DLL with the sensor command blobs.
--state-dir PATH
State directory (default /var/lib/validity).
--log-level LEVEL
error, warn, info (default) or debug.
--trace-sensor-traffic
Log every sensor command, reply and interrupt: opcode, length and status only, never the content.
--session
Serve on the session bus (development).
--address ADDRESS
Serve on the bus at ADDRESS (tests).

Configuration

Every setting is optional; the command line wins. Copy /usr/share/doc/validity-daemon/validity.toml.example to /etc/validity/validity.toml.

state_dir = "/var/lib/validity"
vendor_dll = "/var/lib/validity/vendor/synaWudfBioUsb.dll"
log_level = "info"
ready_timeout_ms = 3000     # Claim / ListEnrolledFingers wait for a sensor coming up
finger_timeout_ms = 30000   # how long a scan waits for the finger

[users]                     # users enrolled under another identity
# alice = "S-1-5-21-111111111-1111111111-1111111111-1000"

Logs

journalctl -u validity-daemon

validity-vendor

Installs the two files the daemon needs from Lenovo's Synaptics driver package nz3gf07w.exe, which may not be redistributed: the driver DLL (sensor command blobs) and the sensor firmware extension. It downloads the package on this machine, checks its SHA-256, extracts the two files, checks theirs, and switches them into place in one atomic step. Already in place and intact: it does nothing and uses no network. The packages run it at installation; run it again as root if the machine was offline then.

validity-vendor install [--archive FILE | --url URL] [--dir DIR]
validity-vendor check [--dir DIR]
--archive FILE
Use a copy of nz3gf07w.exe already on disk (no network).
--url URL
Download from a mirror instead of Lenovo; same SHA-256 check. Default from VALIDITY_VENDOR_URL.
--dir DIR
Installation directory (default /var/lib/validity); files land in DIR/vendor.

Exit status: 0 done or already in place, 1 error, 2 usage error, 3 download failed, 4 (check) files missing or damaged. Password login never depends on these files: without them the reader is simply unavailable.

pam_validity.so and the login profile

A small PAM module that asks the service to verify the user's finger. It succeeds only on a match; anything else (no service, no reader, no finger enrolled, a timeout, an error) fails quickly so the stack falls back to the password. It shows no prompt.

max-tries=N
Fingers refused before the module fails (default 3).
timeout=N
Seconds to wait for a finger per attempt, 1 to 3600 (default 30).
confirm
After a match, say Access granted (for LightDM, whose greeter then waits for Enter).
bus=ADDRESS
Use this D-Bus address instead of the system bus (tests).

Unknown or invalid arguments are ignored: a typo never locks anyone out.

The validity-fprint profile (Debian, Ubuntu)

Off by default. On the LightDM greeter and lock screen the password comes first, as without a reader: type it and you are in. To use the finger, press Enter on an empty password, touch the reader, wait for Access granted, press Enter. Everywhere else (sudo, su, polkit) the finger is asked first for 10 seconds, then the password.

sudo pam-auth-update --enable validity-fprint    # turn it on
sudo pam-auth-update --disable validity-fprint   # back to password only

The profile is never required: the password always works.

Fingerprints (fingerprint-settings)

A one-screen desktop app, in English or French, for people who have never used a fingerprint reader: it registers or removes the right index finger. A progress bar fills with each good touch; a touch that did not take is not an error. Every result is one plain sentence that says what to do next. It works with any fprintd-compatible service.

fingerprint-settings

Or find Fingerprints (Empreintes digitales) in the applications menu. Run it from the desktop session itself: the system asks the session's permission to use the reader.

fprintd's command-line tools

They talk to the same D-Bus API, so they work unchanged:

fprintd-list $USER                         # registered fingers
fprintd-enroll -f right-index-finger       # register a finger
fprintd-verify                              # check a finger
fprintd-delete $USER -f right-index-finger # remove one

Run as root to act on another user.
